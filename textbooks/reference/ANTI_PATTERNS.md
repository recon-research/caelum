# ANTI_PATTERNS — Failure Modes And Their Fixes

The catalog of ways work in `<DOMAIN>` goes wrong, and how to fix each. This is the pre-mortem reference: read the relevant entry *before* building something in an area, and again when it breaks. [SYMPTOMS.md](SYMPTOMS.md) routes plain-language complaints here.

> **Format.** One named anti-pattern per `###` heading, each with four labelled parts:
> - **Symptom** — what you observe (the externally visible bad behavior).
> - **Diagnosis** — the underlying cause, stated honestly.
> - **Fix** — the concrete corrective action (and the better pattern to adopt).
> - **Books** — where the right approach is taught, as plain text "Book NN §X".
>
> Give each entry a memorable name. Write "Book NN" as plain text, never a link. To cross-reference a technique, link the doc: [PATTERNS.md](PATTERNS.md).

## Universal entries — pre-seeded, keep when filling in

Domain-agnostic failure modes every project hits. They ship filled, survive onboarding (the fill-in instruction at the bottom covers the domain entries, not these), and grow via the template's reflux loop — downstream retrospectives that flag a defect cluster as generic contribute it back here.

### "The Self-Reporting Oracle"

- **Symptom:** the suite is green while the feature is wrong — a defect in the computation sails straight through tests that "cover" it.
- **Diagnosis:** the test's only oracle is the implementation's own account of itself: asserting on a returned `count` the same function computed, trusting an emitted summary line, re-asking the code what it just did. Expectation and behavior share one source of truth, so they *cannot* disagree — the test verifies that the code equals the code. (Flagged as generic in a downstream M1 retrospective; adopted upstream via #244.)
- **Fix:** derive the expectation independently of the code under test — a hand-computed constant, an independent recomputation from the raw inputs, a golden fixture. Where only a self-reported value exists, assert an independent invariant on it as well (bounds, conservation, agreement between two distinct code paths). Review-time guard in the same oracle-integrity family: `adversarial_review` Lens C treats changed tests as guilty until proven.
- **Books:** none — universal. Add your domain's testing section here at onboarding if the library covers one.

### "The Untested Refusal"

- **Symptom:** the trust boundary looks defended — input pins, guard clauses, refusal branches are all present in the code — yet the first genuinely hostile input sails through, and nobody can say when any guard last actually fired.
- **Diagnosis:** each *new* pin or refusal branch landed without the tampered input that trips it. The suite exercises only the accept path, so the reject path is dead code whose color no one has ever seen — a refusal no test can fire is indistinguishable from no refusal at all. Trust-boundary sibling of "The Self-Reporting Oracle": there the test *cannot disagree* with the code; here it *never meets* it. (Flagged as generic in a downstream M2 retrospective; adopted upstream via #346.)
- **Fix:** every guard merges with its attack — a committed fixture of the tampered/hostile input plus an assertion that the refusal fires (and fails **closed** where that's the contract). Extending validation means extending the hostile corpus in the same PR; review treats a new refusal branch without a new red-path test as unshipped. Same oracle-integrity family as `adversarial_review` Lens C (changed tests are guilty until proven).
- **Books:** none — universal. Add your domain's trust-boundary section here at onboarding if the library covers one.

### "The Spelling-Changing Wrapper"

- **Symptom:** after adopting a tool that rewrites command invocations, permission prompts storm on commands that were pre-approved for months, and/or guard hooks that reliably fired go silent — with no change to the rules themselves.
- **Diagnosis:** the permission and guard stack is keyed on command *spellings* — allowlist rules like `Bash(git status:*)`, hooks that parse raw command strings — and the wrapper changed the executed spelling (`git status` → `wrap git status`; full-path `gh.exe` vs bare `gh`). It breaks in **both directions at once**: guards are silently evaded (the dangerous one), and allow rules silently stop matching (the noisy one). (Internal precedent: the #418 lesson — merge guards matched only bare-`gh`; externally corroborated by a wrapped-CLI ecosystem's own open priority-high security issue, the same string-match failure seen from the allowlist side — `research/notes/cli-output-compression.md` › Validations, 2026-07.) Third arm, **no wrapper needed**: a new guard *authored* with a bare-binary anchor while a sibling guard already carried the multi-spelling union token — `git.exe` / quoted-full-path / `-C`-intervener commits bypassed the naked-TODO scan for weeks while the commit-message hook judged the very same command string (#559, third sighting of the class).
- **Fix:** first ask whether the guard needs a *command* at all — a trigger expressible as a **tool event** (`Edit|Write|MultiEdit|NotebookEdit`, `AskUserQuestion`) carries no command string, so there is nothing to respell and this whole class cannot reach it; that is structural immunity rather than one more alternation to keep in step. Pyxis's claim reminder moved onto exactly that matcher in #794 (`edit-on-default`), and the same hook now carries both keying styles side by side. Where the trigger genuinely *is* a command (`git add` segments, chained merges), the older rungs still apply: guards normalize or harvest the *executed* spelling rather than assuming the canonical one — or the wrapper is rejected at the design stage. Adopting any invocation-rewriting tool triggers a sweep of every spelling-keyed surface (allow rules, hooks, CI greps) in the same change; a wrapper nobody swept for is a standing hole. And a **new** command-matching guard starts from the family's shared GIT/GH token (the token comments name their siblings — keep the twins in step), never a fresh bare anchor (#559).
- **Books:** none — universal. Frontier evidence: `research/notes/cli-output-compression.md` (notes stale ~2 quarters — re-verify before citing onward).

### "The Char-Count Savings Illusion"

- **Symptom:** an output-trimming tool (or your own filter) advertises huge savings — "60–90% of output stripped" — yet the monthly bill barely moves, or rises.
- **Diagnosis:** percent-of-output-stripped is not percent-of-bill-saved. Bills are dominated by cache-write and output tokens, native truncation already caps the pathological outputs the tool demos on, and much of the tool-output stream bypasses the filter entirely — independent A/Bs measured one marketed "60–90%" compressor at between **−0.5% and +10% real cost** (a 500-session replay and a single-user A/B; sources in `research/notes/cli-output-compression.md`, 2026-07). Characters stripped are the artifact; tokens billed are the bill.
- **Fix:** any output-trimming claim is measured on **billed tokens** before adoption — a pre-registered A/B on real sessions (the EXP-01 method: measure the bill, not the artifact). A percent with no bill behind it doesn't land.
- **Books:** none — universal. Frontier evidence: `research/notes/cli-output-compression.md` (notes stale ~2 quarters — re-verify before citing onward).

### "The Agreeable Fixture"

- **Symptom:** a rule ships with the wrong reading — the flagship number is off ~2×, a flag inverts in deployment — yet every test that covers the rule is exact, independent, and green; the escape surfaces only at a later, wider review.
- **Diagnosis:** the fixtures only visit configurations where the right and wrong readings of the rule *agree*, so the assertions — however exact — never get to disagree with the defect. Two escapes in one downstream milestone: an aggregation rule whose fixtures were all single-group or equal-parameter, hiding anti-conservative cross-group borrowing (max of one factor paired with independently-min of another); an identity flag whose tests all fed one literal spelling, so raw equality held while the deployed environment's different spelling inverted it. Input-side sibling of "The Self-Reporting Oracle": there the assertion *cannot* disagree with the code; here the inputs never *let* it. (Flagged as generic in a downstream M5 retrospective; adopted upstream via #517.)
- **Fix:** for every rule admitting two readings — precedence, tie-break, aggregation, normalization, identity — commit at least one fixture where the readings **diverge**, and pin the correct side. The review question is *"what configuration would make the wrong reading fail?"* — asked per rule, at authoring and at review (`adversarial_review` Lens C carries it as the input-side complement of its oracle checks).
- **Books:** none — universal. Add your domain's testing section here at onboarding if the library covers one.

### "The Prose Invariant"

- **Symptom:** a property everyone agrees the system guarantees — ordering, atomicity, self-healing, idempotence, byte-stability — turns out not to hold, and the suite that "covers" the component was green the whole time. Reviewers find it by reading; no test ever could.
- **Diagnosis:** the invariant was only ever *stated* — in a plan, a docstring, a PR body — and stating it doesn't create an oracle. The tests assert what the code does; nothing asserts the claim, so "tests green" is satisfiable with **zero** coverage of it. The gap is procedural, not intellectual: no step between plan and done demanded a named test per stated invariant, so the check happens at review — the most expensive moment — or never. Oracle-integrity family: "The Self-Reporting Oracle" has an oracle that can't disagree, "The Agreeable Fixture" has inputs that never let it; here there is **no oracle at all**. (Three instances in one downstream milestone, including a heal-behavior mutation that survived the full suite; adopted upstream via #557.)
- **Fix:** make the mapping an artifact, not a memory. Planning emits an **invariants → oracles** table — every asserted invariant paired with the *named* test that will assert it, and a row without a test is a plan gap closed before implementation (`plan_work` step 6); the done-gate re-checks the mapping and fails on an invariant that still lives only in prose (`definition_of_done` gate 2). Where the property resists a direct test, assert its observable consequence (a round-trip, a conservation sum, a replayed sequence) — never leave the row empty.
- **Books:** none — universal. Add your domain's testing section here at onboarding if the library covers one.

### "The Hand-Written Count"

- **Symptom:** a doc names a count, or enumerates in prose a list that lives authoritatively elsewhere — "the five contract items", "the four knobs", "subagents X and Y" — and the copy is stale: the list grew, the count didn't. A reader following the count stops early and drops exactly the newest item.
- **Diagnosis:** counts and in-prose enumerations of growable lists are *derived values written by hand* — they drift by construction the first time the source changes; the single-home rule's violation in miniature. One whole-repo review surfaced four at once: "the five contract items" after item 6 (the oracle-discipline item a literal reader then skips) was appended; "four knobs" heading five knob lines; a directory map naming 2 of 4 agent contracts — the unnamed one silently degrades downstream eval re-earns; three divergent partial enumerations of one CI job across two docs. Prior sighting: a skills-README count sentence, fixed by audit-assertion (#261). (Adopted upstream via #568.)
- **Fix:** don't write the count — point at the list ("the contract items above", "the full list: §6 owns it"). Where a count is genuinely load-bearing, audit-assert it against the source so drift goes red instead of stale (#261's rung); a count neither pointed nor asserted is a standing drift.
- **Books:** none — universal.

### "The Satisfiable-by-Anything Assertion"

- **Symptom:** a capture / UI / integration check stays green while the rendered values are swapped, an enum shows its opposite, or a figure is plain wrong — the check asserted *something*, and something was there.
- **Diagnosis:** the assertion's oracle is weaker than the value it guards: a substring over aggregate text (`includes("involved")` is satisfied by the opposite enum word "uninvolved"; a `"0 m² · Ec 0"` substring matches any area ending in 0), a count where identity matters, presence where exactness matters. Compounded by the **mirror-clone path**: a harness cloned from its sibling re-imports porosity the sibling had already fixed elsewhere in the same file. Oracle-integrity family — the second downstream to hit oracle porosity independently. (Two sightings in one downstream milestone; adopted upstream via #518.)
- **Fix:** scope each assertion to the element that *owns* the value and exact-match it; pair every zero/absence-assertion with a positive that proves the machinery ran; prefer identity pins over counts. When cloning a test or assertion family, copy the **strongest** oracle form in the family, not the oldest. Capture-surface canon: `design_review`'s CAPTURE_CONTRACT.md, contract item 6.
- **Books:** none — universal. Add your domain's testing section here at onboarding if the library covers one.

### "The Unscoped Selector"

- **Symptom:** you add a new component or section and a harness you never touched goes red — in a *different* feature's beats, asserting on code your diff doesn't reach. First instinct is "did I break the old feature?"; the honest answer is no, you widened what its selector matches.
- **Diagnosis:** the harness identifies its subject through a shared vocabulary term — CSS class, log prefix, JSON key, metric label — that was unique only by accident of timing, because it had exactly one producer the day the test was written. A second producer silently widens every unscoped selector: `.reqrow` goes 2 → 4 and an exact `=== 2` fails on correct code. Nothing in the new work's diff points at the old harness, and review is structurally blind to it — `adversarial_review` Lens C treats *changed* tests as guilty, and here no test changed. Inverse of "The Satisfiable-by-Anything Assertion", which shares its fix but not its direction: there a weak oracle passes a wrong value; here a correct, exact oracle fails correct code because its subject moved underneath it. (Flagged as generic in a downstream M7 retrospective; adopted upstream via #587.)
- **Fix:** the moment a term gains its **second** producer, scope every harness selector to the section that owns it. Treat "I am reusing an existing class/prefix/key for a new component" as itself the trigger to grep every harness for the bare term **in the same slice** — the near-miss is the whole lesson: the prior slice had already scoped its *new* selectors and never retrofitted the *existing* harnesses, so the collision merely waited a slice. Partial application of the correct fix is what lets this through. Don't rename the shared term to dodge it — sharing the class is usually correct, and the scope belongs in the test, which is the thing making the identity claim.
- **Books:** none — universal.

### "The Wider Teardown"

- **Symptom:** unrelated things break moments after a *successful* verification step — modules that resolve everywhere else stop resolving, a config or fixture directory is empty, a branch or table is gone. The errors name a subsystem the change never touched, so the first hour goes into "what did I break in `<subsystem>`?" when the answer is "nothing — it was deleted".
- **Diagnosis:** the check needed a fixture, so something was created, exercised, and then removed — and the teardown's blast radius was wider than the setup's. `mkdir -p` is *idempotent and silent*: it gives no signal whether it created the directory or merely found one that already held real work, and the matching `rm -rf` cannot tell those cases apart either. Same shape for any create/destroy pair whose destroy half takes a container — dropping a schema to remove a table, `git branch -D` on a name that pre-existed, removing a whole output dir. The template *induces* it: the done-gate demands liveness evidence, and the honest way to evidence a **guard** is to plant something bad and show it goes red, so gate slices systematically create-then-delete in the working tree. (Downstream sighting: four tracked components deleted by a liveness fixture's cleanup, surfacing two steps later as module-not-found errors during an unrelated typecheck; recovered only because everything was committed. Adopted upstream via #738.) Evidence-side sibling of the family where *producing* the evidence has effects the guidance never named — the other arm is pasting a gate's own findings as evidence and re-committing what it caught (`definition_of_done` › Output carve-out).
- **Fix:** remove exactly the paths you created, never a parent — `rm -f <the one file>`, not `rm -rf <the dir>`. Where a container is genuinely needed, make collision impossible by construction: a uniquely-named leaf, a `mkdtemp`-style path, or the session scratchpad whenever the check can reach it. Then `git status` immediately after cleanup, while the damage is still attributable — the failure's whole cost is the distance between the deletion and the symptom.
- **Books:** none — universal.

### "The Half-Closed Class"

- **Symptom:** a bypass was found, fixed, and pinned — the corpus now carries several named evasion cases, each with a comment explaining the escape it closes — and the *plain* sibling of every one of those spellings still walks straight through. It is always the **next** review that finds it, never the one that wrote the fix.
- **Diagnosis:** the fix is validated against the *instance* that prompted it, and the regression case records that instance. The class it belongs to is never enumerated, because the instance arrived pre-packaged as a finding, and finding-shaped work feels complete when the finding is closed. **The tell is asymmetry in the corpus** — the obfuscated member pinned, the obvious one absent, which is backwards, since the obvious one is what an ordinary caller types. Three instances in one downstream milestone: a judge-rule pack denying `env FOO=1 git push` and `$(git push)` while allowing `FOO=1 git push`, `` `git push` ``, `{ git push; }` and `/usr/bin/git push`; a doc gate that closed its code-span escape but left the route detector keyed to three URL prefixes, so a real route outside them stayed invisible; a client fixed for name-only matching while the shipped contract doc kept teaching name-only uniqueness. Corpus-side member of the oracle-integrity family: "The Agreeable Fixture" has inputs that never *let* the assertion disagree, whereas here every case does discriminate — and the set of them is a fraction of the class. (Downstream lesson, adapted from the reporter's own text; adopted upstream via #736.)
- **Fix:** name the **axis** the bypass varies along — prefix form, quoting form, path form, tool name, doc-vs-code — and add a case per point on it, **including the boring one**; pair every new deny case with a must-**not**-deny neighbour, which makes the boundary explicit and catches the over-broad repair in the same breath. *A fix whose corpus grew by exactly one case is unfinished.* **Mutation-checking is the mechanical version of naming the axis** — perturb the guard, watch which cases die, and read **a mutation that kills zero cases as a corpus gap, not a passing grade** (upstream instance: dropping a keyword matcher's word boundary killed zero of five carefully-chosen evasion fixtures — the boring case was the one missing, #727). Two riders, both learned from batteries run against this repo's own gates: score a kill only when it arrives as a **FAIL line**, since a mutation that kills by *crash* never ran the assertion — the one exception is a guard admitting no non-crashing wrong answer, which you demonstrate by **splitting** the guard rather than by asserting it (#679); and assert over the guard's whole output, not the half the fix touched — a case watching one returned field while the damage lands in the other kills nothing (#729).
- **Books:** none — universal. Add your domain's testing section here at onboarding if the library covers one.

### "The Guard That Advertises More Than It Enforces"

- **Symptom:** a guard's own documentation describes reach it does not have — "matches namespaces, filenames and folder names", "keeps the two sides running the same gates" — and it runs green for months while the advertised half has never once fired. Nobody misread it; it over-claimed for itself, in its own header.
- **Diagnosis:** the claim is true of the *matcher* and false of the *corpus fed to it*. "Handles folder names" is not a claim about a regex, it is a claim about what reaches the regex — and the two drift apart silently, because every green run reads as evidence for the sentence sitting above it. **A half-true advertisement is the durable kind:** it survives review precisely because the part a reviewer spot-checks is correct. One level up from "The Prose Invariant" — there an untested property of the *code* was only ever stated; here it is an untested property of the *guard*, which is why it recurs in codebases that already fixed the first. Two upstream instances, each found by the review *after* the guard shipped: a name-leak scanner whose header promised folder-name coverage for four months while the scan walked file *contents* only, so a clean file under a directory named after a sibling project produced zero hits — its selftest even carried a case named `hit: underscore folder form` that asserted on a *mention* of a folder inside a line of file text (#739); and a preflight/CI mirror whose header promised the two sides run the same gates while the check compared **script names** only, so a `--strict` flag present locally and absent in CI stayed green for the file's entire life (#725, closed by #729).
- **Fix:** for every capability a guard's prose claims, **name the corpus that capability is exercised over and check that a fixture visits it** — a claim with no fixture behind it gets covered *or* narrowed in the same change, never left standing. Prefer narrowing when covering is expensive: a guard that describes exactly what it does is worth more than one describing what it ought to. And treat a fixture that borrows the claim's *vocabulary* while exercising the covered half as the tell — that is this entry and "The Agreeable Fixture" in the same three lines.
- **Books:** none — universal.

### "The Guard That Lives in the Harness"

- **Symptom:** a safety check that you wrote, that works, and that would have stopped you — skipped, because this time the dangerous act took a shorter route. The tooled version of the operation refuses unsafe input correctly; the few lines typed inline to do the same thing do not, and the inline version is the one that runs whenever the job feels too small to set up properly. Afterwards the rule turns out to have been written down, correctly, in a place you had already read.
- **Diagnosis:** the rule was attached to the **tool** while the hazard belongs to the **situation**. Anything reachable by an ad-hoc path therefore ships its guard only on the path nobody takes when hurried — and "too small to bother" is not a random mood, it correlates with the hazard, because the operations worth doing inline are the quick ones and quick ones get done mid-flow on uncommitted work. Two upstream instances of one operation: a mutation battery whose restore step is `git checkout -- <file>`, which recovers HEAD rather than the work under test. First it left an untracked file un-restorable mid-run and then erased uncommitted logic wholesale (#471); the rule was written into the harness's header and honoured by every persisted battery thereafter — and the *next* destruction was a five-line inline loop that reproduced the restore semantics without the refusal (#746). Distinct from "The Wider Teardown", which is about a destroy step's blast radius: here the blast radius is exactly right and the *baseline* is wrong. Distinct from "The Guard That Advertises More Than It Enforces": that guard's reach is overstated, this one's reach is accurate and simply not on the path taken.
- **Fix:** prefer making the hazard **structurally absent** over guarding it, because a structural fix cannot be outrun by haste. For the worked example: restore from a copy you made — `cp` the target aside first and `cp` it back — never from version control, and no baseline can be handed back that isn't the work under test, committed or not. Where a guard is genuinely the only option, put it in the **operation's own path** rather than in the wrapper (a pre-commit hook rather than a lint script, a refusal inside the destructive function rather than in the CLI that usually calls it), and state the hazard's *situation* in the rule's text — "when validating something you just wrote" — so a reader recognises the moment rather than only the tool.
- **Books:** none — universal.
