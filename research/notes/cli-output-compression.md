# CLI-output compression for agent workflows — the rtk question

> reviewed: 2026-07-30 · tiers: the closed vocabulary in README rule 2 (the audit prints it on error)

The owner asked (2026-07-22, #495) whether Pyxis should integrate [rtk-ai/rtk](https://github.com/rtk-ai/rtk) — a CLI proxy marketed on large self-reported token savings for agent workflows — or borrow its ideas. This note grounds that adopt/borrow/reject call against the template's token-discipline machinery (CLAUDE.md › Token discipline; the spelling-keyed permission allowlist; the PreToolUse guard hooks). Raw sweeps: three preserved verbatim on #495 (survey class: 3 agents · ~30 sources fetched).

## State of the art

### What rtk is (mechanism)

- rtk ("Rust Token Killer") is a single-binary Apache-2.0 Rust CLI proxy that deterministically filters/compresses command output before it reaches the agent's context — no LLM summarization, no caching; strategies are smart filtering, grouping, truncation, deduplication [production-proven] (source: https://github.com/rtk-ai/rtk, accessed 2026-07-22)
- Invocation is a prefix wrap (`git status` → `rtk git status`); `rtk init -g` instead installs a Claude Code **PreToolUse hook** that transparently rewrites Bash commands, so the model keeps emitting bare spellings [production-proven] (source: https://github.com/rtk-ai/rtk, accessed 2026-07-22)
- The shipped hook returns `"permissionDecision": "allow"` with reason "RTK auto-rewrite" plus `updatedInput` carrying the rewritten command on every successful rewrite — i.e. it auto-approves its own rewrites past Claude Code's permission layer [production-proven] (source: https://raw.githubusercontent.com/rtk-ai/rtk/master/hooks/claude/rtk-rewrite.sh, accessed 2026-07-22)
- Claude Code's built-in Read/Grep/Glob tools bypass the hook entirely (README's own caveat); the hook also deliberately skips pipes, `&&`-chains, command substitutions, heredocs, and absolute-path invocations [production-proven] (source: https://github.com/rtk-ai/rtk, accessed 2026-07-22; corroborated: https://blog.jetbrains.com/ai/2026/07/rtk-claude-code-token-savings/, https://github.com/rtk-ai/rtk/issues/3148, accessed 2026-07-22)
- Failure handling is a **tee pointer**: on command failure the full unfiltered output is saved to disk and the filtered output carries a pointer line (`FAILED: 2/15 tests [full output: ~/.local/share/rtk/tee/…]`), so the model can recover detail without re-running [production-proven] (source: https://raw.githubusercontent.com/rtk-ai/rtk/master/docs/usage/FEATURES.md, accessed 2026-07-22)
- Maturity: created 2026-01-22 (6 months old), ~72.6k stars, 823 open issues + 871 open PRs, latest stable v0.43.0 (2026-06-28) with near-daily 0.44.0-rc pre-releases; ~89k Homebrew installs/365d [experimental] (source: https://api.github.com/repos/rtk-ai/rtk, https://formulae.brew.sh/formula/rtk, accessed 2026-07-22)

### The claims vs the measurements

- Self-reported: "60–90%" headline; README session table totals −80%, footnoted "Estimates"; website claims "89% avg. noise removed" across 2,900+ commands — all measured as characters stripped from raw output, not billed tokens [experimental] (source: https://github.com/rtk-ai/rtk, https://www.rtk-ai.app, accessed 2026-07-22)
- JetBrains paired A/B (rtk v0.43.0, Claude Code 2.1.201, claude-sonnet-5, SkillsBench 86 tasks, 425 billed trials): with-rtk was median **+7.6% more expensive per task at low reasoning effort (p=0.004)**, +13.8% turns (p=0.03); at high effort ±0.1% (p=0.99); task quality statistically tied [published] (source: https://blog.jetbrains.com/ai/2026/07/rtk-claude-code-token-savings/, accessed 2026-07-22)
- Codepointer replay of 500 real Claude Code sessions (614M tokens, $926.31 baseline): rtk alone saved **0.5% of spend ($4.65)**; rtk+headroom+caveman combined 3.7%; **78% of tool-output tokens bypass rtk's hook** via built-in tools [published] (source: https://codepointer.substack.com/p/cutting-llm-token-costs-with-rtk, accessed 2026-07-22)
- LogDx-CI benchmark (11 context-reduction tools × 35 real GitHub Actions failures): hybrid grep+tail routers dominate the cost-quality Pareto frontier (top two 0.670/0.666 at ~$0.03/case); rtk's three standalone modes land bottom-4, and rtk-log confidently misleads the LLM on ~13.3% of cases (best hybrid uses rtk-err-cat as one fallback stage — useful component, poor standalone) [published] (source: https://arxiv.org/abs/2605.28876, accessed 2026-07-22; mode-level scores from the PDF: https://arxiv.org/pdf/2605.28876, accessed 2026-07-22)
- Independent Gemini CLI A/B (single user): +10% tokens with rtk — the CLI's native truncation had already capped the pathological output rtk compresses; author uninstalled [experimental] (source: https://tomoharutsutsumi.medium.com/the-over-optimization-trap-why-i-uninstalled-my-ai-token-optimizer-399fb68c5f7e, accessed 2026-07-22)
- The gap is structural, not tuning: bills are dominated by cache-write and output tokens; the stream rtk compresses is largely cheap cache-read re-sends (~1/10th input price), native truncation already caps the worst outputs, and compression-induced re-reads add a retry tax [published] (source: https://blog.jetbrains.com/ai/2026/07/rtk-claude-code-token-savings/, https://codepointer.substack.com/p/cutting-llm-token-costs-with-rtk, accessed 2026-07-22)
- The positive coverage volume (dozens of articles, HN "confirmations") traces back to rtk's own char-count scoreboard and README table, including posts by rtk core-team members; no fetched third-party source reproduced anything near 60–90% on billed tokens [experimental] (source: https://news.ycombinator.com/item?id=46974740, https://news.ycombinator.com/item?id=48588755, accessed 2026-07-22)

### Permission-layer interactions (load-bearing for any hook-based wrapper)

- rtk's hook historically ran commands past ask-by-default without prompting (their #886, filed as a security issue); the shipped fix is the `permissionDecision: "allow"` auto-approval above — the bypass became the design [production-proven] (source: https://github.com/rtk-ai/rtk/issues/886, https://raw.githubusercontent.com/rtk-ai/rtk/master/hooks/claude/rtk-rewrite.sh, accessed 2026-07-22)
- Open, priority-high, area:security (filed 2026-07-22): rewritten spellings no longer match user allowlists — `Bash(grep *)` rules stop matching once the executed command is `rtk grep`, causing spurious permission prompts [production-proven] (source: https://github.com/rtk-ai/rtk/issues/3152, accessed 2026-07-22)

## Rejection — integrating rtk into the template

Rejected 2026-07-22 (this survey; owner ratifies via #495). The whys, so no future harvest re-litigates blind:

1. **No measured benefit at the bill.** Every rigorous independent measurement (JetBrains A/B, Codepointer replay, LogDx-CI, the Gemini A/B) lands between half a percent of spend *saved* and ten percent of cost *added*, against a marketing claim built on character counts (sources above).
2. **It defeats the template's permission posture by design.** The hook auto-approves its own rewrites (`permissionDecision: "allow"`) — Pyxis policy is the opposite: agents cannot widen permissions, by design (`docs/AUTOMATION.md` §2), and denials are decision points routed to the owner (CLAUDE.md › permission denial). Installing rtk's hook would silently ratify every rewritten command.
3. **It breaks the spelling-keyed stack — in both directions.** Pyxis allow rules are bare spellings (`Bash(git status:*)`, `.claude/settings.json`), and the guard hooks parse raw command strings (`block_naked_todos` harvests `git add` segments — #492; `block_chained_merge`; `inject_rule_reminders` path rules, behind its `Bash|PowerShell` matcher). A `rtk git …` executed spelling evades every **command-keyed** guard — the #418 lesson class (full-path `gh.exe` vs bare-`gh` matchers), now externally corroborated by rtk's own #3152, which is the same string-match failure seen from the allowlist side.
4. **The addressable stream here is small.** Pyxis is a docs/process repo whose broad reads are delegated to read-only subagents (paths-not-payloads, EXP-01) and built-in tools — the very streams that dominate the bypass share measured above.
5. **Maturity + supply-chain surface.** Six months old, 823 open issues, near-daily RCs, `curl | sh` install, and a hook layer interposed on every shell command — the class's compromise blast radius is arbitrary command execution (Codepointer's XZ-Utils analogy, source above).

## Validations — what Pyxis borrows

1. **The tee-pointer failure pattern.** Full output to a file, short summary + pointer in-context, model reads the file only when needed — rtk's genuinely good idea, and exactly the shape LogDx-CI's winners use. Candidate: preflight/test wrappers emit `FAILED … [full log: <path>]` instead of full dumps.
2. **Billed-tokens-or-it-didn't-happen.** The char-count illusion (percent-of-output-stripped ≠ percent-of-bill-saved) is now an externally documented failure mode; it re-validates EXP-01's method (measure the bill, not the artifact). Any future output-trimming claim in this repo must be measured on billed tokens.
3. **Hybrid routers over clever filters for huge logs.** grep+tail composition beat every bespoke filter on CI-failure diagnosis at ~$0.03/case (source above) — the recipe if a CI-log-diagnosis step ever lands here.
4. **Anti-pattern harvest:** (a) spelling-changing wrappers break spelling-keyed permission/guard stacks; (b) char-count savings claimed as cost savings. Both landed in `textbooks/reference/ANTI_PATTERNS.md` (#496, shipped 2026-07-23; re-verified against the entries and the post-#310 hook stack — the claims in §3 still hold). Re-verified again 2026-07-28 (#605) after the staleness audit date-compared this note against `ANTI_PATTERNS.md`: the change that tripped it was #596's *"The Unscoped Selector"* (`15f054c`, shared-vocabulary test selectors), which neither supersedes nor touches 4a/4b — a true re-verify prompt, answered, no claim edits. Re-verified a third time 2026-07-29 (#735) on the same trigger: the new entry was #738's *"The Wider Teardown"* (fixture teardown wider than its setup), again orthogonal to 4a/4b — three prompts, three no-ops, which is what a warn-only date comparison is expected to produce most of the time. **Re-verified a fourth time 2026-07-30 (#798), on both triggers at once** — `.claude/settings.json` (#794 + its #799 ratification, #751's landing-block hook) and `ANTI_PATTERNS.md` (#781 mutate-restore, #766 the Half-Closed Class, #741 gate-evidence): 4a/4b are intact and unsuperseded, but unlike the previous three this prompt was **not** a no-op — #794's tool-event matcher is a real refinement to 4a, recorded as item 5 below and as a scope fix in §3. Three no-ops then a hit is the yield a warn-only comparison exists for; a gate that had been silenced after the second no-op would have missed it.

5. **Where a guard can hang off a tool event, the spelling problem disappears.** #794 moved the claim reminder off command-string matching onto the `Edit|Write|MultiEdit|NotebookEdit` event (`edit-on-default`, `.claude/hooks/inject_rule_reminders.py`). There is no command string to respell, so anti-pattern 4a's evasion class cannot reach it at all — **structural immunity, not another alternation to maintain**, which is the difference between a fix that holds and one that needs sweeping every time a sibling guard is authored (#559's third arm). So this is the first rung to try when a guard's trigger is expressible as a tool event; normalize-the-executed-spelling remains necessary only where the trigger genuinely *is* a command (`git add` segments, chained merges). Verified 2026-07-30: `inject_rule_reminders` now carries three matchers — `Bash|PowerShell`, `AskUserQuestion`, `Edit|Write|MultiEdit|NotebookEdit` — so both keying styles coexist inside one hook, which is why §3's claim above is *scoped* to command-keyed guards rather than withdrawn. The rtk rejection is unaffected: a wrapper still breaks every command-keyed surface, and most of this repo's guards are still command-keyed by necessity. Landed in `textbooks/reference/ANTI_PATTERNS.md` 4a's Fix ladder, which is where a pre-mortem will actually read it.

## Candidate experiments

- **EXP: transcript token composition** — hypothesis: under a quarter of this repo's tool-result tokens flow through Bash output, mirroring the 22% share Codepointer measured on real sessions [published] (source: https://codepointer.substack.com/p/cutting-llm-token-costs-with-rtk, accessed 2026-07-22); metric: share of tool-result tokens by tool class over the local transcript corpus; baseline: Codepointer's replay. Filed #498 — **run as `EXP-08`, SUPPORTED (2026-07-23):** fleet-wide Bash share 22.7% of tool-result chars (bar: <25%), Read/Grep/Glob 70.7%; the split behind it — sidecar transcripts carry 57.3% of the stream at only 8.1% Bash while main sessions run 42.3% (pyxis main-only 50.9%) — i.e. delegation already moved the read-heavy bulk off the main window, and what remains there is the Bash residue. Composition ≠ cost (cache-read economics unchanged); the wrapper rejection stands.
- **EXP: tee-pointer preflight** — hypothesis: pointer-style failure output cuts billed tokens per red-preflight recovery without hurting fix success; metric: billed tokens + recovery outcome across N failures, A/B vs full dumps; baseline: current full output. Filed #497 — **run as `EXP-09`, REFUTED (2026-07-23):** success parity 15 of 15 in both arms, but median billed cost per recovery *rose* under the pointer arm (0.156 → 0.196 USD, median ratio 1.26; the large-dump scenario inverted hardest, 0.169 → 0.224 despite the in-context dump shrinking 10,037 → 1,052 chars). Mechanism: the read-the-log round trips re-send the growing context as fresh input, swamping the saved dump chars — the survey's cache-economics skepticism measured directly on this repo's own gates. Cost case dead; only a context-window-occupancy redesign (not per-recovery price) could revive the idea.
