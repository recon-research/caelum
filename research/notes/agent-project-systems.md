# Agent-operated project systems — the external landscape

> reviewed: 2026-07-17 · tiers: the closed vocabulary in README rule 2 (the audit prints it on error)

Pyxis's bet — a project operated by agents from a tracker, with docs as caches, evidence-gated done, and self-tuning process machinery — is not being made in a vacuum: spec-driven methodologies, agent memory systems, agent-native process tooling, and SOP-encoded multi-agent frameworks all attack overlapping parts of the same problem. This note surveys that landscape, grounds the #301 harvest program (#302–#312), and records the validations and rejections as decision ammunition so future harvests don't re-litigate them.

Provenance: four web sweeps by session research agents, 2026-07-16/17; the raw sweeps with every source, tier call, and unverified-flag are preserved verbatim as comments on pyxis#301. Accessed dates below are as stamped by the fetching agents.

## State of the art

### Spec-driven methodologies

- GitHub Spec Kit is the category leader by adoption (121,780 stars, 193 releases, claimed integration with "30+ AI coding agents"): a /specify → /plan → /tasks → /implement pipeline over a nine-article "constitution", with a Phase -1 compliance gate — constitutional violations require a filled-in justification table, not vibes — and templates that mandate `[NEEDS CLARIFICATION]` markers on every ambiguity instead of plausible-assumption filling [production-proven] (source: https://github.com/github/spec-kit, stars via https://api.github.com/repos/github/spec-kit, accessed 2026-07-16)
- OpenSpec (61,220 stars) splits truth from proposal: `openspec/specs/` holds current requirements while each active change carries only its requirement *delta* (added/modified/removed), archived on ship in the same motion that updates the canon [production-proven] (source: https://github.com/Fission-AI/OpenSpec, accessed 2026-07-16)
- BMAD-METHOD (50,700 stars, v6.10.0) centers the story file: a planner agent pre-compiles a cited context payload into the work artifact (Dev Notes, source-path citations, tasks numbered to the acceptance criterion they satisfy), the implementer's writes are partitioned to declared regions of that file, and a Dev Agent Record captures model used / files touched / completion notes as a structured execution receipt [production-proven] (source: https://github.com/bmad-code-org/BMAD-METHOD, story template fetched from src/bmm-skills/4-implementation/, accessed 2026-07-16)
- AWS Kiro writes acceptance criteria in EARS grammar (five SHALL templates), scopes steering docs by declared inclusion mode (`always` / `fileMatch` glob / `manual` / `auto`), and runs agent hooks where exit code 2 blocks execution and returns the error to the agent — the same contract as Claude Code PreToolUse hooks [production-proven] (source: https://kiro.dev/docs/specs/, https://kiro.dev/docs/steering/, https://kiro.dev/docs/hooks/, accessed 2026-07-16)
- Kiro also scales ceremony to risk: full approval-gated Requirements → Design → Tasks phases, or a "Quick Plan" mode that runs all three phases without approval gates for well-understood features [production-proven] (source: https://kiro.dev/docs/specs/, accessed 2026-07-16)
- Agent OS (5,073 stars, smallest surveyed by an order of magnitude) contributes one distinctive move: Discover — generate the standards layer by mining the existing codebase for patterns rather than authoring it from scratch [production-proven] (source: https://buildermethods.com/agent-os, stars via https://api.github.com/repos/buildermethods/agent-os, accessed 2026-07-16)
- The ecosystem converged post-release on "specs drift; you need a reconcile verb": Spec Kit grew /speckit.converge (assess the *codebase* against the artifacts) and OpenSpec built archive-on-ship — the problem pyxis solved from the tracker side first [production-proven] (source: https://github.com/github/spec-kit/blob/main/spec-driven.md, https://github.com/Fission-AI/OpenSpec, accessed 2026-07-16)

### Memory & context persistence

- Cline Memory Bank: six markdown files in an explicit rate-of-change cascade (near-immutable brief → slow context docs → fast active-state files), all read before every task — but the bank *is* the truth: updates are manual and holistic, there is no external reconciliation source, and token overhead is unaddressed in the docs [production-proven] (source: https://docs.cline.bot/prompting/cline-memory-bank, accessed 2026-07-16)
- Letta (MemGPT lineage) gives every always-in-context memory block a schema-enforced hard character limit plus `read_only` flags, and offloads curation to a background sleep-time agent that asynchronously rewrites the primary agent's blocks between interactions — memory management as a separate, cheaper job from the work [production-proven] (source: https://docs.letta.com/guides/agents/memory-blocks, https://www.letta.com/blog/sleep-time-compute/, accessed 2026-07-16)
- Claude Code memory is best-in-survey on decay: the auto-memory index loads only its first 200 lines / 25KB and over-limit writes get a rewrite-forcing error; `.claude/rules/*.md` with `paths:` frontmatter load only when matching files are touched; /doctor trims CLAUDE.md by a derivability test (cut what the codebase can answer; keep pitfalls, rationale, deltas-from-default); root CLAUDE.md is re-injected after /compact while nested files are not [production-proven] (source: https://code.claude.com/docs/en/memory, accessed 2026-07-16)
- AGENTS.md standardizes location and precedence only (nearest file in the directory tree wins), with adoption across 60,000+ open-source projects and the major non-Claude harnesses — the cross-tool interop floor [production-proven] (source: https://agents.md/, accessed 2026-07-16)
- Devin Knowledge attaches a required trigger description to every memory item, auto-suggests new items from in-chat corrections, and proposes updates to *existing* items rather than only appending — a structured correction→durable-memory pipeline with a human approval gate [production-proven] (source: https://docs.devin.ai/product-guides/knowledge, accessed 2026-07-16)
- Windsurf runs an explicit two-tier capture→promotion model: auto-memories land in a local, uncommitted, workspace-scoped buffer, and the docs direct durable team knowledge to be promoted out into versioned rules/AGENTS.md [production-proven] (source: https://docs.devin.ai/desktop/cascade/memories, accessed 2026-07-16)
- mem0 reconciles at write time — each extracted fact is checked against existing memories and dispatched ADD / UPDATE / DELETE / NOOP, so contradictions are resolved by the writer, not discovered by readers — reporting 26% relative improvement over OpenAI's memory, 91% lower p95 latency, and >90% token savings vs full context on LOCOMO [published] (source: https://arxiv.org/abs/2504.19413, accessed 2026-07-16); A-MEM adds memory *evolution*: new memories trigger updates to the representations of linked old ones [published] (source: https://arxiv.org/abs/2502.12110, accessed 2026-07-16)

### Process tooling

- Beads (25.4k stars): a git-backed issue tracker with agents as the primary users — `bd ready` returns unblocked work in one query, `bd update --claim` makes claiming an atomic verb, dependency edges are typed. Its own author documents the failure modes: agents don't proactively use it, the DB becomes un-greppable for agents past ~500 issues, and hygiene is a daily chore (`bd doctor` daily, cleanup every few days) [experimental] (source: https://github.com/steveyegge/beads, https://steve-yegge.medium.com/beads-best-practices-2db636b9760c, accessed 2026-07-16)
- The Ralph loop (bare while-true re-prompting, all state re-anchored from disk each iteration) documents its own failure taxonomy — assumption bias duplicating work, placeholder implementations gaming the reward, waking to a broken build — and its guards: one item per loop, validation subagents capped at 1 while search fans wide, and "signs" added to the prompt the moment a misbehavior is observed; the author expects ~90% completion with "unspecified latent behaviours" and rejects the loop for existing codebases outright [experimental] (source: https://ghuntley.com/ralph/, accessed 2026-07-16)
- Compounding engineering (Every; plugin at 23.2k stars) adds a fourth loop step — Compound: every code review's findings are summarized into standing instructions that later plan runs read; it ships a lessons lifecycle (/ce-compound-refresh updates stale learnings) and the pruning heuristic "ten specific rules outperform 100 generic ones"; self-reported feature time-to-ship fell from over a week to 1–3 days [experimental] (source: https://every.to/chain-of-thought/compound-engineering-how-every-codes-with-agents, https://github.com/EveryInc/compound-engineering-plugin, accessed 2026-07-16)
- claude-flow/Ruflo (64.7k stars) markets swarm topologies, hive-mind consensus, and vector memory; the one hands-on review measured ~120k tokens for init alone and 220k+ before a medium feature starts, found "every cold start behaved exactly like the first one" despite the claimed learning system, and caught the queen agent overriding explicit user intent [experimental] (source: https://github.com/ruvnet/claude-flow, review: https://chenguangliang.com/en/posts/claude-code-multi-agent-orchestration-plugins/, accessed 2026-07-16)
- TDD Guard demonstrates the enforcing tier of hooks: a PreToolUse hook that asks a configurable second model whether the pending edit violates TDD given current test state, blocks on violation, and returns *what to do instead* — model-judged blocking rather than pattern-matched advice, with over-implementation (code beyond what tests require) as a blockable violation class [experimental] (source: https://github.com/nizos/tdd-guard, accessed 2026-07-16)
- Cost-per-merged-PR is emerging as the field's unit of agent cost, and the recommended fleet pattern is per-agent × per-task attribution with trace IDs to prevent double-counting (the vendor's overrun statistics are unverified — see Watch) [experimental] (source: https://keito.ai/blog/multi-agent-cost-tracking/, accessed 2026-07-16)

### SOP frameworks & lab guidance

- MetaGPT (69.4k stars) encodes SOPs as prompt sequences with typed artifact handoffs between roles; its ablations price the mechanisms: executable feedback cut human revision cost 2.25 → 0.83 (worth more than any single role), role decomposition lifted executability 1.0 → 4.0 while raising tokens 19k → 31k, and the full system scores 85.9% HumanEval / 87.7% MBPP Pass@1 [published] (source: https://arxiv.org/abs/2308.00352, repo https://github.com/FoundationAgents/MetaGPT, accessed 2026-07-16)
- ChatDev (ACL 2024) runs asymmetric instructor/assistant pairs through phase dialogues; its communicative-dehallucination ablation — the assistant must request missing specifics before answering, never guess — is worth Quality 0.3094 → 0.3953 on its own, and removing role assignments drops executability 0.88 → 0.58 [published] (source: https://arxiv.org/abs/2307.07924, accessed 2026-07-16)
- Anthropic's engineering guidance codifies poka-yoke tool design (make misuse structurally impossible rather than advisory), an escalation ladder ending in Stop hooks as deterministic turn-end gates, verification subagents in fresh context ("the agent doing the work isn't the one grading it"), and the warning that a reviewer prompted to find gaps will report some even when the work is sound [production-proven] (source: https://www.anthropic.com/engineering/building-effective-agents, https://code.claude.com/docs/en/best-practices, accessed 2026-07-16)
- Anthropic's multi-agent research system beat single-agent Opus by 90.2% on their internal eval, with token budget alone explaining 80% of performance variance — and costs to match: agents ≈ 4× chat tokens, multi-agent ≈ 15×; their prompts embed explicit effort-scaling rules (how many subagents/tool calls a query class deserves) [production-proven] (source: https://www.anthropic.com/engineering/multi-agent-research-system, accessed 2026-07-16)
- Anthropic's Agent Skills post prescribes evaluation-first authoring — run agents on representative tasks, observe where they struggle, then write the skill, and keep monitoring the triggering surface [production-proven] (source: https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills, accessed 2026-07-16); Voyager is the published ancestor of the admission gate — a skill enters the library only after iterative verification against environment feedback, compounding to 3.3× unique items vs prior SOTA [published] (source: https://arxiv.org/abs/2305.16291, accessed 2026-07-16)
- Procedures can be evolved from evidence rather than taste: Agent Workflow Memory induces reusable workflows from an agent's *successful* trajectories for +24.6% (Mind2Web) and +51.1% (WebArena) relative success rate [published] (source: https://arxiv.org/abs/2409.07429, accessed 2026-07-16); GEPA mutates procedure text via natural-language reflection on failure trajectories, beating GRPO by +6% average (up to +20%) with up to 35× fewer rollouts — reflection-driven mutation is affordable where RL-style search never would be [published] (source: https://arxiv.org/abs/2507.19457, accessed 2026-07-16)
- SOP-following is measurably unreliable even with expert-authored SOPs: SOP-Bench (2,000+ tasks, 12 domains) finds model-agent success rates of 57%–100% depending on domain with no dominant combination, and model upgrades can silently regress — ReAct scored 72.4% with Claude 4 Opus vs 63.3% with Claude 4.5 Sonnet [published] (source: https://arxiv.org/abs/2506.08119, accessed 2026-07-16)

## Validations (decision ammunition — why pyxis's shape stands)

- Ralph's self-documented failure modes — placeholder implementations gaming the reward, assumption bias duplicating work, waking to a broken build — are precisely the holes PR-gated slices, DoD evidence, and CI close; the loop's own author caps expectations at ~90% completion with "unspecified latent behaviours" and refuses it on existing codebases [experimental] (source: https://ghuntley.com/ralph/, accessed 2026-07-16)
- Cline Memory Bank is the canonical counter-example that motivates docs-are-caches: narrative state that *is* the truth, with no external reconciliation source, so drift has nowhere to be caught — the failure the truth order (git/CI > tracker > docs) is built to prevent [production-proven] (source: https://docs.cline.bot/prompting/cline-memory-bank, accessed 2026-07-16)
- The field independently converged on the Status-anchor design — small always-loaded state under hard size budgets (Letta's per-block character limits; Claude Code's enforced 200-line/25KB index; Windsurf's 6,000/12,000-character rule caps; Cursor's under-500-line guidance) and root-anchored state as what survives compaction [production-proven] (sources: https://docs.letta.com/guides/agents/memory-blocks, https://code.claude.com/docs/en/memory, https://docs.devin.ai/desktop/cascade/memories, https://cursor.com/docs/context/rules, all accessed 2026-07-16)
- AFlow's acceptance rule — a workflow mutation is kept only on measured improvement over the incumbent, worth +5.7% average over hand-designed SOTA across six benchmarks — is external validation of the EXP-NN pre-registration discipline for process changes [published] (source: https://arxiv.org/abs/2410.10762, accessed 2026-07-16)
- MetaGPT and ChatDev each win on their own benchmark (ChatDev's rubric scores MetaGPT's executability 0.41; MetaGPT's rubric scores ChatDev 2.25 of 4) — a live demonstration for pyxis's blind-protocol / neutral-filename rule: never let a procedure's author grade it on their own rubric [published] (source: https://arxiv.org/abs/2307.07924, https://arxiv.org/abs/2308.00352, accessed 2026-07-16)
- Cheap diverse reviewers beat a padded orchestration layer: three sequential diverse-model reviewers scored 30%+ higher bug detection at under $0.10/task in the same hands-on review that measured Ruflo's overhead — a cost datapoint confirming adversarial_review's fan-out shape [experimental] (source: https://chenguangliang.com/en/posts/claude-code-multi-agent-orchestration-plugins/, accessed 2026-07-16)
- No ecosystem equivalent was found, across all four sweeps, for the guard-hits telemetry ledger and guard lifecycle, for cost receipts posted onto the merged PR itself, or for template reflux; the closest neighbors (community hook gates, cost-per-PR discussion, one-way template sync) each stop short. Absence of evidence from four searches, not proof — the raw sweeps on #301 record the search surface.

## Rejections (decision ammunition — recorded so future harvests don't re-litigate)

- **Spec-as-source-of-truth** (Spec Kit's "code serves specifications"; OpenSpec's standing canon): a second cache that drifts — the exact disease the truth order exists to prevent; adopt the gates and delta formats, refuse the inversion (source: https://github.com/github/spec-kit/blob/main/spec-driven.md, accessed 2026-07-16)
- **Synchronous phase approval gates** (Kiro's Requirements → Design → Tasks sign-offs): block the autonomous loop on a human; provisional-proceed + objection window + silence-ratifies is the async replacement already in place (source: https://kiro.dev/docs/specs/, accessed 2026-07-16)
- **Persona role-play layers** (BMAD's 12+ specialized roles; persona reviewers elsewhere): prompt-level discipline, strictly weaker than pyxis's harness-enforced tool restrictions — the adversarial reviewer is read-only by toolset, not by request (source: https://github.com/bmad-code-org/BMAD-METHOD, accessed 2026-07-16)
- **Beads as the tracker**: a second source of truth beside GitHub Issues, carrying its own documented costs — agents forget to use it, un-greppable past ~500 issues, a daily hygiene regime — while its good ideas (ready-work query, machine-readable blocking edges, epic-close compaction) port to `gh` without the datastore (source: https://steve-yegge.medium.com/beads-best-practices-2db636b9760c, accessed 2026-07-16)
- **Vector-store memory sidecars** (mem0's store, Letta archival, Ruflo's AgentDB): duplicated unreconciled state; at pyxis scale the grep-able, CI-reconciled tracker is the archival tier — adopt mem0's write-time ADD/UPDATE/DELETE/NOOP discipline, refuse the store (source: https://arxiv.org/abs/2504.19413, accessed 2026-07-16)
- **Chat-chain phase architecture** (ChatDev): dialogue-phase handoffs are dominated by PR-gated slices with CI on verifiability; executability on toy software does not transfer to a real repo's definition of done (source: https://arxiv.org/abs/2307.07924, accessed 2026-07-16)
- **MCTS workflow search and open-ended meta-agent invention** (AFlow's search machinery; ADAS): both require a scored benchmark harness per workflow and budgets pyxis's one-shot slices don't have — keep AFlow's acceptance rule and ADAS's design-archive concept, reject the search (source: https://arxiv.org/abs/2410.10762, https://arxiv.org/abs/2408.08435, accessed 2026-07-16)
- **Swarm/hive-mind orchestration** (Ruflo): measured six-figure token overhead before work begins, no demonstrated learning, intent-override behavior — the anti-pattern the token-discipline and decision-window policies exist to prevent [experimental] (source: https://chenguangliang.com/en/posts/claude-code-multi-agent-orchestration-plugins/, accessed 2026-07-16)

## Pyxis feasibility path

The harvest is filed as the #301 program. #302 (per-skill golden tasks) lands first — it is the admission gate every later procedure change regression-tests against, and the piece the SOP-Bench / GEPA / Voyager line of evidence points at most directly; #303 and #310 depend on it. The remaining slices (#304–#309, #311, #312) are independent of the goldens and of each other, and land in whatever order sessions reach them. Everything adopted here enters through the normal route — ticket-first slices, an EXP-NN wherever a claim must be measured locally before it changes policy — and nothing in this note supersedes a settled D-NN. Scope and acceptance criteria live in the ticket bodies, not here.

## Candidate experiments

- Context-payload tickets A/B (the BMAD story-file hypothesis): matched slices run from pointer-only tickets vs tickets carrying a pre-compiled, cited context payload; metric: per-slice PR cost receipts plus count of re-discovery reads; baseline: current pointer tickets.
- Goldens catch a seeded regression: seed deliberate defects into candidate SKILL.md diffs; hypothesis: the #302 golden set blocks them pre-merge at a higher rate than prose review; metric: detection rate over the seeded set, judged blind.
- Lesson-harvest effect on repeat findings: enable review→lesson harvest for one milestone; metric: repeat-finding rate in adversarial_review (same finding class recurring across later reviews) vs the prior milestone's rate mined from tracker history.

## Watch

- BMAD's ~90% token-savings claim for story-file context payloads is third-party and unverified — directionally plausible; do not cite as measured until the context-payload experiment prices it locally [experimental] (source: https://redreamality.com/garden/notes/bmad-method-guide/, accessed 2026-07-16)
- Claude Code's native OTel cost metric with `skill.name`/`agent.name` attributes — attribute list search-surfaced only, the official doc page was not independently fetched; verify before any OTel-fed metrics-ledger spike [experimental] (source: https://signoz.io/blog/claude-code-monitoring-with-opentelemetry/, accessed 2026-07-16)
- Keito's overrun statistics (orgs with 5+ agents seeing 35–50% cost overrun attributed to attribution gaps) are vendor-published with unverified methodology — use the attribution pattern, not the numbers [experimental] (source: https://keito.ai/blog/multi-agent-cost-tracking/, accessed 2026-07-16)
- The sleep-time-compute paper (arXiv:2504.13171) is cited only via Letta's blog — fetch it directly before it grounds anything [experimental] (source: https://www.letta.com/blog/sleep-time-compute/, accessed 2026-07-16)
- SOP-Bench's regression-on-model-upgrade finding implies re-running the skill golden set whenever the session model changes; watch SOP-Bench revisions and the related SOPBench (arXiv 2503.08669, existence-verified only) at next review [published] (source: https://arxiv.org/abs/2506.08119, accessed 2026-07-16)
- Kiro's task-to-requirement numeric back-references are widely reported but not confirmed on the fetched official pages — partially unverified [experimental] (source: https://teachmeidea.com/kiro-ai-ide-spec-driven-development/, accessed 2026-07-16)
- **Re-check before any orchestration-layer decision:** did Anthropic restrict third-party agent frameworks for Pro/Max subscribers on 2026-04-04? Reported in search summaries only, never fetched — so it is an open question here, not a finding.
