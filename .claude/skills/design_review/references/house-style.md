# House Style — the default register

This file ships the template's default aesthetic register — ORRERY — plus the alternates built and approved for contrast. It is the default, not a mandate: projects with their own taste do not edit this file directly (it is overwritten wholesale on every template sync). Instead, point the Design-surfaces knobs in `PROJECT_CONVENTIONS.md` at a project-owned style doc, or promote the canon into a project-owned design book via `build_library` (the D-137 promotion path). Improvements to the shared default flow upstream via the template's inbox lane.

> **Provenance:** distilled from Fable-model design sessions, 2026-07 (D-137). HALCYON's full section and ORDINATE were deliberately re-derived from the #149 frozen collections (2026-07) — canonicalization ledgers in the [exemplar gallery README](exemplars/README.md).
> **Register names** — ORRERY, WAYMARK, HALCYON, TESSERA, ORDINATE, SEXTANT — are fictional demo brands invented for this template; they name no real product. A name-scrub-sensitive downstream can fork-and-own the register text freely (the original ORRERY gallery goldens render the register name into their headers — #183 tracks that gap; the #149-era goldens render fictional *product* wordmarks instead, so they scrub with the text).

## ORRERY

The owner's confirmed taste. Default to this register for ops/tactical/sim tools; consciously depart for other subjects.

**Tokens:**
```js
const T = {
  bg: "#070B12",        // deep blue-black, never pure black
  surface: "#0D1420",
  surface2: "#121B2B",
  line: "#22304A",
  lineSoft: "#182338",
  ink: "#DCE6F2",
  muted: "#5F7189",
  faint: "#3A4A63",
  amber: "#FFB454",     // command / attention / AI
  cyan: "#57D4DD",      // telemetry / live data
  red: "#FF5C5C",       // threat / abort / untrustworthy
  green: "#7BD88F",     // nominal / healthy / recommended
  display: "'Chakra Petch', sans-serif",   // wordmarks, section titles, buttons
  mono: "'IBM Plex Mono', monospace",      // all data, coords, timestamps, logs
  body: "'IBM Plex Sans', sans-serif",     // prose, help text
};
```

**Rules of the house:**
- **Amber/cyan duotone with semantic roles** — amber means "command/attention/AI-originated," cyan means "live telemetry." Never decorative. Green and red reserved for judgment (healthy/nominal vs threat/invalid).
- **Corner-bracketed panels** (four L-shaped ticks at panel corners) are the structural motif — not chamfers, not rounded cards, not shadows. 1px borders in lineSoft; headers separated by a rule, titled with a letterspaced uppercase eyebrow plus an optional mono tag on the right.
- **Square geometry**: zero border-radius; diamonds (rotated squares) for status pips; triangles for own-ship; open squares for targets.
- Display face only for wordmarks, eyebrows, and buttons — letterspaced 0.12–0.22em uppercase. Everything data-bearing is mono.
- Every screen has something alive: a ticking clock, drifting telemetry, an appending log. Stillness reads as broken in this world.
- Core primitives to reuse: Panel (corner-bracketed), Eyebrow, Readout (mono label + big tabular value + unit), Sparkline, GaugeArc, TrackRow (diamond pip + id/kind + range), CmdButton (outlined uppercase, fills on hover; danger = red).

## HALCYON

Editor chrome — the register for content-creation tools, where the user manipulates a
world or document through dense docked panels. Three idioms share one skin: docked
multi-panel chrome, timeline/keyframe editing, and node-graph canvases. Exemplar:
`exemplars/editor-register/scene-editor.jsx` (+ its `tokens.js`), goldens in `exemplars/golden/`.

*(Enriched from a one-line alternate by the #149 canonicalization. One descriptor superseded on evidence: "periwinkle selection" → the warm selection accent — all three independent derivations in the frozen collection converged on warm, and every cool channel below carries a fixed functional meaning, so a cool selection accent would collide with typed hues.)*

**Tokens:**
```js
const T = {
  /* warm graphite ramp — chrome only, never data */
  bg0: "#141110",       // deepest: menu, tab strips, status bar
  bg1: "#191513",       // workspace background
  panel: "#1E1A16",
  raised: "#27221C",    // hover / active surfaces
  inset: "#100D0B",     // wells: inputs, lanes, search
  line: "#2E2822",      // hairlines
  line2: "#3D352B",
  ink: "#EFE9DE",
  mut: "#A89E8F",
  dim: "#6E6659",
  amber: "#F2A64B",     // THE accent: selection · current frame · unsaved · primary action
  ok: "#7FBE79", warn: "#D9AE4F", err: "#E05B4E",   // judgment only
  /* fixed-meaning functional families — never decorative, never re-mapped */
  axisX: "#DE5F49", axisY: "#7FB851", axisZ: "#5C8CDB",          // gizmo/channel axes
  tMesh: "#6FA3DC", tLight: "#D9BE66", tCamera: "#B78FDB",       // object-type badges
  tVolume: "#54B7A6", tSpawn: "#7CC286", tSeq: "#DD8FB1", tGroup: "#93887A",
  pFloat: "#7FCB9B", pVector: "#A98FE8", pColor: "#E3BE5C", pTexture: "#E88BA4", // port types
  ui: "'Public Sans', 'Segoe UI', system-ui, sans-serif",        // chrome, labels
  mono: "'Spline Sans Mono', 'Cascadia Mono', Consolas, monospace", // every number, path, log
};
```

**Rules of the house:**

- **Warm graphite, ONE selection amber.** Amber means *what you have selected, the current
  frame, what is unsaved, the primary action* — and is spent nowhere else. The chrome must
  recede behind a scene that can be any color; and because every cool channel below carries
  a fixed functional meaning, warm is the only accent that can never be mistaken for data.
- **Functional hues are datatypes, not decoration.** X is always this red, Y this green,
  Z this blue — on gizmo arrows, inspector field spines, channel dots, key tints. Object
  types (mesh/light/camera/volume/spawn/sequence) keep one badge hue each; ok/warn/err are
  judgments only. A seventh decorative color means the design is wrong.
- **Channel-color discipline (timelines).** A transform channel wears its axis hue
  everywhere it appears — rail dot, key diamonds, curve stroke — so `translate.y` is "the
  green one" in every panel, legible with no legend. Keys are diamonds; group/summary rows
  get hollow diamonds.
- **One time spine.** A single frame→pixel mapping drives the dual-unit ruler (frames over
  seconds — so f↔s can never silently drift), event flags, every lane, and any curve plot.
  The playhead is one unbroken bright-ink vertical crowned by an amber frame flag: the
  playhead is *attention, not alarm* — red stays reserved for record-arm and destructive
  acts. Every count on screen (keys, events, durations) is derived from the key data at
  render time, never hand-written twice.
- **Docked chrome anatomy, and one selection on four surfaces.** Menu bar → toolbar →
  docked panels (tree | viewport | inspector) → timeline strip → a single-line status bar
  that mirrors the newest console event and carries the perf truth (ms and fps must
  convert; the readout breathes — a frozen perf counter reads as a hung editor). The
  selected object appears simultaneously in the tree row, the viewport (outline + gizmo),
  the inspector header, and the status bar — same name, same numbers, one source.
- **Bright scene, quiet chrome.** Viewport content may be any luminance — a pale alpine
  morning inside dark tool furniture is the genre's truth. Gizmos, selection outlines and
  in-scene labels carry dark under-halos so they read on any scene; never tint the scene
  toward the chrome.
- **Node canvases speak in typed ports.** Port and wire hues encode the datatype
  (float/vector/color/texture) at both ends and along the wire — connection legality is
  visible before you drag. Wires are horizontal-out cubic beziers over a dark halo stroke;
  node headers carry their kind hue as a top rule; selection re-uses the amber; the cost
  truth (instruction counts, budgets) lives once in the status strip and is repeated, never
  re-derived by hand.
- **Dense tool furniture, mono data.** 10–13px type on a 4px grid (tool furniture, not prose —
  the craft rule's ≥16px body floor is for reading prose, which editor chrome doesn't carry;
  the wider ramp rides its dense-tool carve-out, #191), 22–24px rows, mono for
  every number, path and log line, tabular numerals throughout; mixed-case names,
  letterspaced uppercase only on micro-eyebrows; square panels with tab strips, controls
  rounded 4–6px. Density is the genre's honesty — an editor is a cockpit, and airiness
  reads as a toy.

**When to choose it:** reach for HALCYON when the user *authors* rather than *operates* —
scene editors, sequencers and timeline tools, shader/material/behavior node graphs, asset
pipelines. When the subject is monitoring and commanding a live world, that's ORRERY;
when it's reading and comparing data, that's ORDINATE.

## ORDINATE

The analysis register. Reach for it when the screen's job is *reading and comparing recorded
data* — overlaid metric curves, run/config comparisons, dense result tables — and the reader
leaves with a decision. The dark-dashboard genre is this subject's native language; ORDINATE
stays in the house's world (graphite-blue dark, semantic accents, mono data) but spends its ink
on the evidence instead of the chrome. Exemplar: `exemplars/analysis-register/run-comparison.jsx`
(+ its `tokens.js`), goldens in `exemplars/golden/`.

**Tokens:**
```js
const T = {
  bg: "#0C0F16",         // graphite blue-black — dark-dashboard native, never pure black
  surface: "#121722",
  surface2: "#19202E",
  line: "#29334A",
  lineSoft: "#1E2637",
  ink: "#E6EBF4",
  muted: "#94A0B3",      // secondary READING tone — holds ≥4.5:1 on surfaces
  faint: "#5B6880",      // chrome/de-emphasis only — never the sole carrier of text users must read
  amber: "#F0B25B",      // attention / AI-originated / focus ring (house semantic)
  green: "#5ECF95",      // pass / healthy / recommended (house semantic)
  red: "#FF6B65",        // fail / regression / untrustworthy (house semantic)
  series: ["#5FA9FF", "#B78AF7", "#3FD0C9"],  // run identity ONLY — never judgment
  display: "'Space Grotesk', 'Segoe UI', sans-serif", // wordmark + screen title only
  body: "'IBM Plex Sans', 'Segoe UI', sans-serif",    // labels, prose, legends — mixed case
  mono: "'IBM Plex Mono', 'SFMono-Regular', Consolas, monospace", // tabular data + axes
  r: 4,                  // one quiet radius — chips and buttons; panels stay hairline
};
```

**Rules of the house:**

- **The chart is the hero.** The primary plot gets the widest column and reading-size type —
  axis labels, legends, and annotations at ≥10px in `muted` or better, never `faint`. Chrome
  never competes: hairline panels, hierarchy by ink, not furniture. *Why: the screen's job is
  reading; every pixel of decoration is stolen from the evidence.*
- **Open with the finding, not the furniture.** A one-sentence plain-language lede states what
  the data shows, with the load-bearing values visually marked (mono, underlined). The screen
  argues; the panels below are its evidence. *Why: analysis surfaces exist to close a decision —
  the sentence is the decision's summary and its sanity check at once.*
- **Mixed-case wherever reading speed matters.** Uppercase-with-tracking survives only on the
  wordmark. Section titles, column headers, legends, and buttons are mixed-case `body`; data is
  mono. *Why: letterspaced all-caps micro-type measurably slows scanning on data-dense screens
  and reads as costume, not instrument.*
- **Uncertainty is rendered, not asserted.** Solid = final/trusted; dashed = still moving;
  hollow marks = sparse or unverified samples, with CI whiskers sized from the actual n; every ±
  names its n and method in a provenance footer; missing data stays blank with a stated why.
  *Why: expert readers trust a screen that shows its error bars — confidence drawn honestly is
  what separates evidence from decoration.*
- **Series colors are identity; judgment colors are verdicts.** The blue/violet/teal ramp only
  distinguishes runs/cohorts/series (cap ~4 — more overlay is spaghetti, not comparison); green/
  red/amber keep their house semantics (pass/fail/attention) and are never spent decoratively.
  *Why: color is the fastest channel on a chart — spending it twice makes both meanings
  unreadable.*
- **Numbers interlock or don't ship.** Every repeated value matches everywhere it appears;
  every derived value survives recomputation (deltas from their endpoints, columns summing to
  headers, rates × durations agreeing, counts consistent between header, table, and legend).
  Compute derived values from one data source rather than hand-copying. Tabular numerals on all
  data. *Why: expert audiences recompute — one broken cross-check poisons trust in every other
  number on the screen.*
- **Every chart teaches its own reading.** Healthy zones are drawn ON the plot with the label
  inside; a plain-language verdict chip says what the chart concludes and why; a one-line
  how-to-read subtitle decodes the texture (band/dash/hollow); annotations name mechanisms
  ("curriculum v3 enters cluttered totes — expect the dip"), not just positions. *Why: replace
  documentation with feedback — the verdict is how users learn to read the chart.*
- **Static honesty over fake liveness.** An analysis dataset is a frozen artifact: stamp it
  ("data through …"), state its provenance, and let it hold still — no ticking clocks, no
  drifting values. The house "something alive" rule belongs to monitoring surfaces. *Why: on an
  evidence surface, motion implies the evidence is still changing — stillness here reads as
  rigor, not breakage.*

**When to choose it:** default to ORDINATE when analysis IS the screen — the user came to read,
compare, and decide, not to watch or command. Keep ORRERY (with its derate rules) when an
analysis *moment* lives inside a monitoring or command surface that stays in the terminal idiom;
keep TESSERA when the subject wants print-flavored daylight — reports, lab notebooks, documents —
rather than a dark instrument.

## SEXTANT

The handheld register — the house's world translated to the phone. Named for the handheld
navigation instrument: ORRERY is the control room; SEXTANT is what you carry into the
field. It is a *form-factor* register: it skins app surfaces (M3-grounded Compose) and
game HUDs alike, and pairs with a subject register's judgment rules rather than replacing
them. Exemplars: `exemplars/mobile-register/fleet-companion.kt` (portrait app, both
themes) and `exemplars/mobile-register/storm-hud.kt` (landscape game HUD, scene-driven
dark) + shared `tokens.kt`/`primitives.kt`; goldens in `exemplars/golden/`. Pixel path:
`CAPTURE_CONTRACT.md` › JVM-offscreen Android (#250).

**Tokens** (`mobile-register/tokens.kt`, Kotlin — dark shown; light re-derives accents to
hold ≥4.5:1 as ink on white):
```kotlin
bg 0xFF0B0F16 · surface 0xFF111722 · surface2 0xFF18202E
line 0xFF26314A · lineSoft 0xFF1C2536
ink 0xFFE4EAF4 · muted 0xFF93A0B5 · faint 0xFF5A6780   // faint: chrome only
amber 0xFFF5B04E · cyan 0xFF4FD2DB · green 0xFF63D08F · red 0xFFFF6259
display Chakra Petch · mono IBM Plex Mono · body Roboto (the platform's own face)
rTouch 12dp · rInstrument 0dp · minTarget 48dp · row 56dp   // 4dp rhythm
```

**Rules of the house:**

- **One-thumb law.** Primary action lives in the bottom third at ≥48dp; list rows 56dp;
  destructive never adjacent to primary. The actionable alert docks as a **command tray
  above the nav bar** — attention and its actions never sink below the fold of a scroll
  column.
- **Rounded where the thumb lands, square where data lives.** Touch surfaces (buttons,
  nav, sheets, tappable cards) take the M3 12dp radius; instrument readouts, plots, and
  data rows stay square. The corner-bracket motif survives only on the hero instrument
  panel — phone hairlines make brackets noise anywhere else.
- **The platform's own body face.** Display face for wordmark/eyebrows/buttons, mono for
  every number, Roboto for prose — the register lives inside the platform, not against
  it. Identity comes from tokens, instruments, and copy, never from fighting Material.
- **Semantic accents carried whole** (amber command/attention · cyan telemetry · green
  nominal · red threat, reserved), spent as one chain per screen. M3 grounding: the
  tokens map into a `ColorScheme` (primary=amber, secondary=cyan, tertiary=green,
  error=red) so Material components inherit the register.
- **Edge-to-edge honesty.** Everything routes through `safeDrawing` insets; game-HUD
  clusters anchor to the safe rect, never the display corners; every HUD glyph over a
  scene carries a dark under-halo (bright-scene rule, inherited from HALCYON).
- **Both themes for app surfaces** — a phone app that ignores light mode is a defect,
  and sunlight legibility is this register's whole job; scene-driven game surfaces are
  legitimately dark-only, stated in the ledger.
- **Feel is out of the goldens' reach.** Stills gate composition, readability, touch
  geometry, and safe-area discipline; motion, timing, and touch response stay
  human-playtested (the gallery ledger states the limit).

**When to choose it:** the surface ships on a phone. Pair it with the subject's register
rules — a monitoring app keeps ORRERY's semantics (as the BOSUN exemplar does), an
analysis screen keeps ORDINATE's chart rules — SEXTANT owns the ergonomics, the platform
mapping, and the type/shape law.

## Alternate registers

Built and approved for contrast — depart to these when the subject calls for it:

- **WAYMARK** survey-chart (buff paper, double-rule legend panels, contour ochre, cartographic route red, serif italic place names).
- **TESSERA** Swiss-lab (cool paper, hard top border on cards, deep-teal data ramp, one ochre anomaly highlight).

## Choosing a register

Default to ORRERY for ops/tactical/sim tools — control-room subjects, where it repeatedly wins blind judging. HALCYON is the home for authoring tools — the user *makes* rather than monitors; ORDINATE for analysis screens — the user *reads and decides*. SEXTANT is the form-factor register: any surface that ships on a phone wears it, layered under the subject register's judgment rules. WAYMARK and TESSERA are approved departures for when the subject genuinely calls for a different world. A register beyond these six is a design decision, not a style tweak — plan it via the two-pass process in `design-craft.md` and record the choice project-side.

**Derate the terminal idiom for data-dense analysis subjects.** When the screen's job is *reading and comparing data* — overlaid metric curves, config diffs, dense comparison tables — rather than monitoring and commanding, the dark-dashboard genre is the subject's native language, and full ORRERY dress measurably loses to it in blind judging (upstream calibration: EXP-03/EXP-04 — judges credited the register's distinctiveness and still docked dense all-caps mono, low-contrast micro-type, and terminal density that fights chart legibility). Staying in-house there means relaxing, deliberately:

- **Mixed-case labels** wherever reading speed matters — letterspaced uppercase stays on eyebrows and buttons only.
- **Chart type at reading sizes** — axis labels, legends, and annotations step up from micro-mono; the chart is the hero, so it gets the ink and the whitespace.
- **Calmer density** — fewer panels, no chrome competing with the data; hierarchy by ink, not by furniture.
- **Contrast floors hold everywhere** — muted/faint tones are for chrome, never for data the user must read.

Or depart outright: ORDINATE (above) is the dedicated analysis register — reach for it when analysis is the screen's whole job rather than a moment inside an ops surface. Non-negotiable in any register: semantic accents, something alive on monitoring surfaces, tabular numerals on live data.
