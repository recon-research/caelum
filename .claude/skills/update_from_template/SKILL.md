# Update From Template

> **Invocation:** this skill sets `disable-model-invocation: true` — a deliberate command you run explicitly (`/update_from_template`), never auto-routed from plain English. It's the worked example for the skill-listing token convention in [`.claude/skills/README.md`](../README.md) › *Authoring conventions* (resolves #6) — don't strip the flag without reading that note.

The template is two kinds of files — the boundary lives in its README (§ *Machinery vs content*): **machinery** (skills, hooks, agents, audit tools, scripts, CI structure, authoring templates) is taken from upstream wholesale; **content** (the filled-in docs and books) is never overwritten — improvements to its *structure* are ported by hand from the diff. This skill makes the first mechanical and the second explicit.

> **Two files, split by *how* you read them (#810).** This one is read in order: seven steps, each rule carrying the clause that says what ignoring it costs. [`SYNC_REFERENCE.md`](SYNC_REFERENCE.md) is read with a key in hand — classification buckets, per-path reconciliation, the constants roster, port routing, and the **field record** behind the rules here.

## Procedure

1. **Locate upstream + the baseline.** Read `TEMPLATE_VERSION` (`source:` + `sha:`). **Resolve a checkout before concluding anything is unreachable (#737):** `source:` is upstream's identity (a URL or slug); `source_path:` — or, pre-#737, `source:` itself — is a local checkout that may not exist on *this* box. Resolve `<source>` in order: `source_path:` if it resolves · else clone `source:` to scratch · else `git -C <the stamped path> remote get-url origin` and clone that. **A path that doesn't resolve here means you are on a different machine, never that upstream is gone.** Resolved one by hand? Fix the stamp at step 6. No stamp? Reconstruct: find the template (ask if unknown), pick the closest baseline by diffing a few machinery files against its history, write the stamp. A `copied_dirty: true` stamp (#243) means the baseline is approximate — diff the listed `dirty_files` at content level before applying, and drop the pair at this sync's re-stamp.
   - **Pin the target once — a ref is not a target (#609) — and the fetch is not optional (#686).** `git -C <source> fetch origin && TGT=$(git -C <source> rev-parse origin/main)`, then read every upstream file at *that sha* (`git -C <source> show $TGT:<path>`), never at a branch name. Both mistakes yield a plausible sha naming the wrong tree: an unfetched clone ports work upstream has already superseded, and a source on an in-flight `slice/*` branch pulls **unmerged upstream work into a downstream, ahead of the template's own merge gate**. Sync the *published* branch (substitute the source's default where it isn't `main`). Pinned, a mid-sync upstream move becomes an explicit choice — fold it in and re-verify, or stamp what you synced. Then `git -C <source> log --oneline <sha>..$TGT` — empty means up to date; report and stop.
2. **Ticket + branch.** File the sync as a tracker issue (label per your project's conventions — no dedicated sync label ⇒ use your general one, e.g. `followup`; #158 hit this downstream) and branch per conventions — a template update rides the normal PR gate like any other change.
3. **Machinery — overwrite from upstream** (the README boundary table is authoritative; re-check it each sync, it can grow). **"Wholesale" means upstream files replace their counterparts — never that downstream-local files are deleted**: diff `git ls-tree HEAD -- <dir>` against upstream first and preserve every file present only downstream (a derived skill, a local hook or agent). The `rm -rf && cp -r` reading is the trap — it can delete a live downstream hook and lock you out of the shell that would restore it (#466, hit live; recovery in the field record). The table also carries **per-feature adoption notes** for conditionally-applicable machinery — read them before wiring those features (#469/#470/#472/#690).
   - **Classify before applying — the opening move (#610).** Don't read a 300-file diff; split it first. For every machinery path present at `$TGT`, compare *committed* blobs three ways with `rev-parse --verify -q` — downstream `HEAD:<p>`, baseline `<sha>:<p>`, target `$TGT:<p>` — and take the **first** matching row of [`SYNC_REFERENCE.md`](SYNC_REFERENCE.md) › *Classification buckets*: absent downstream ⇒ take it · at target ⇒ no-op · untouched since baseline ⇒ take upstream · a blob upstream also has ⇒ dirty-copy artifact, take upstream · otherwise ⇒ **genuine downstream edit, hand-judge**. The dirty-copy row also recovers a missing `copied_dirty` pair after the fact (#243). Needs a full local clone; a shallow one has no old blobs, so everything falls to hand-judging — never to a silent overwrite.
   - **The cited-artifact bucket — the one classification that crosses the table (#689).** The rows above sort a path by its *edit state*; this sorts it by *trust level*, and the two are independent — an artifact can be a clean `new upstream file → take it` **and** be load-bearing machinery that a dozen skills cite. Ask upstream, at the pinned target rather than the source worktree (#609):

     ```bash
     TMP=$(mktemp -d) && git -C <source> archive $TGT | tar -x -C "$TMP"
     python3 "$TMP/scripts/audit_ops_config.py" --root "$TMP" --cited-artifacts
     ```

     Every `research/` artifact something cites, **with its citers and their line numbers**, heaviest first — from the same resolver `audit_ops_config` enforces with, so a citation cannot exist without entering the bucket. **A target in it is machinery whatever directory it sits in:** its citers arrive wholesale in this very step, so declining it is N dangling citations and a red first post-sync preflight, not a deviation you record and forget. Decline only by porting the citers too, and read the *citer list*, not the count. **Empty output is a failure, not a clean bill** — the command exits non-zero for it, because to this reader silence and consent look identical.
   - **Re-read that bucket every sync — it is the only thing that dates a deviation (#689).** **A deviation is a decision with a shelf life:** nothing else signals that a file you correctly declined has since become load-bearing, and one such decline silently became 15 hard FAILs (D-615). Re-reading each sync is the whole of the coverage for that half; the field record states what it still cannot see (#703-shaped, so said rather than papered over).
   - **Two time-sinks before you read a big diff, both existing rules invisible from where you're standing (#613):** *EOL* — a `.gitattributes` broader than upstream's makes `git archive` extraction read as "every file modified", so renormalize first, or compare committed blobs as above and sidestep it; *encoding* — shelling out to read upstream is where `subprocess.run(..., text=True)` mojibakes (`PROJECT_CONVENTIONS.md` › *Python machinery encoding discipline*, #296).
   - **The wholesale set:** `.claude/skills/` · `.claude/hooks/` · `.claude/agents/` · `textbooks/tools/` · `research/tools/` · `textbooks/LIBRARY_SEED.md` · `textbooks/books/00_TEMPLATE.md` · `research/*/00_TEMPLATE.md` · `scripts/` · `.github/`. Overwriting is half the job — most of these owe you something back afterwards. **Walk the row for every directory you overwrote:** [`SYNC_REFERENCE.md`](SYNC_REFERENCE.md) › *Per-path reconciliation* names each and what skipping it fails on the first post-sync run.
   - **Project-mirrored constants — reconcile, never copy.** A machinery constant that names *your* project's reality is a filled stage body in disguise, so a verbatim copy is a regression rather than an update, usually a red first post-sync run. The roster is **single-homed** in [`SYNC_REFERENCE.md`](SYNC_REFERENCE.md) › *Project-mirrored constants* (#685) — walk it before overwriting `scripts/` or `.claude/hooks/`. **Sweep rule when you extend the machinery:** a constant the audits compare against a project's real config belongs in that roster.
   - **A relocated guard reads downstream as a deleted one (#647).** The diff shows enforcement *leaving* a file and never *arriving*: the compensating logic lands in another file, another stage, under a name sharing no tokens with what was removed — so the deletion reads as a weakening and gets "responsibly" re-added, restoring the duplication the move existed to remove. **Half-mechanizable, and the cheap half is worth running:** `git -C <source> diff <sha>..$TGT -- scripts/audit_ops_config.py` — every gate name that *left* `PREFLIGHT_TO_CI` or `CI_ONLY_STEPS` is a relocation candidate; for each, read the commit that removed it (`git -C <source> log -S'<step name>' --oneline <sha>..$TGT`), whose message states where the check went. The map names no destinations and never saw hook-or-inline enforcement, so treat the list as a floor, not a census.
   - `.claude/settings.json` — hook/deny updates apply; **never widen `permissions.allow` beyond the project's current grants as a side effect of a sync** — surface upstream allowlist changes to the owner and let them say yes in their own words. That includes **D-210 dual-spelling entries** (`python3` twins of granted `python` commands), surfaced with the note *"dual spelling of an existing grant (D-210)"*: the agent never adjudicates a trust boundary case-by-case (#277).
4. **Content — port by diff, never overwrite:** root `CLAUDE.md`, `PROJECT_CONVENTIONS.md`, `docs/`, the filled `textbooks/` docs (`CLAUDE` / `README` / `AGENT_GUIDE` / `MANIFEST` beyond `skills[]`), the books, and everything in `research/` that isn't a template or a skill-grounding note (those synced wholesale in step 3). Read the upstream diff for each and port the structural improvements into the filled versions, respecting the project's documented deviations.
   - **Two routing rules decide what a ported paragraph may carry**, both keyed to what you're holding — full rules, gates, and worked shapes in [`SYNC_REFERENCE.md`](SYNC_REFERENCE.md) › *Per-artifact port routing*. **Upstream `#NN` refs (#300):** template-lineage docs (`PROJECT_CONVENTIONS.md`, `textbooks/reference/*`) keep them; downstream-owned docs (root `CLAUDE.md`) never take a bare upstream ref — translate to sync-date provenance or drop it, since the number names a live unrelated issue on *your* tracker. **Research cites (#627):** notes travel; a **report** (`RR-NN`) cite either brings the report *and* the data its `## Reproducibility` names, or drops the path and keeps the finding in prose — never half-ported, because `audit_ops_config` resolves the whole namespace (#625) and a cite with no report goes red, correctly.
5. **Verify.** Full preflight green; all audits green (library + research + skills catalog); spot-check that re-applied stage bodies still execute. Fix before proceeding — a half-applied sync is worse than none. A **newly-adopted doc budget** (count or width) failing on *your* docs is the gate working, not a sync defect (#232) — route by the debt's size (#276): **small debt** (a few lines) ⇒ a same-PR compression, and the budget's own FAIL text carries the rewrite rule; **milestone-narrative-scale debt** ⇒ don't absorb a judgment-heavy content rewrite into a machinery sync: keep the pre-gate audit as a **recorded deviation**, file a lean-then-re-adopt ticket, and state both in the sync PR body (field numbers: #241).
6. **Re-stamp + ship — the re-stamp is the sync PR's *last commit*, not an afterthought.** Update `TEMPLATE_VERSION`: `source:` = the resolvable remote (correcting a pre-#737 path stamp in passing); `sha:` = **`$TGT`, the pinned sha you actually synced** — never a freshly-resolved upstream HEAD, which after mid-sync motion stamps commits nobody read (#609, #686); `last_update:` = today. Nothing on disk forces this step, so a sync that advances the machinery but forgets the stamp silently poisons the *next* sync's baseline, caught only by hand-diffing disk against the stamp (#171, hit live). PR with the evidence; the body names which upstream changes were deliberately **not** taken and why — those are the project's deviations, and future syncs read them.
7. **Report upstream — close the feedback loop.** Gather what this sync learned that belongs to the *template*: upstream defects hit live (each with the local commit/PR that fixed it here), local improvements worth upstreaming, deviations that expose a template flaw, FYIs for future syncs. Findings ⇒ **one issue per sync** on the upstream repo's intake lane — free-form is fine; upstream's `triage_inbox` decomposes it into rigorous tickets and replies with a receipt (read it at the next sync):
   `gh issue create --repo <upstream> --label inbox --title "Template sync report: <project> @ <old-sha>..<new-sha>" --body-file <tempfile>` — `<upstream>` from `TEMPLATE_VERSION` `source:` (a URL names the repo; a local checkout via `git -C <source> remote get-url origin`). Any failure — no slug, no `gh` access, missing label, or the classifier denying the cross-repo write — ⇒ fall back to a **paste-ready feedback block** in the session summary for the owner to relay by hand; an expected path, not a defect (#124). No findings ⇒ file nothing and say "no upstream findings this sync" in the PR body. This `--repo` write is **sanctioned path (1)** in `PROJECT_CONVENTIONS.md` › Merge policy, so no per-sync owner grant is owed (#708); anything beyond this one lane is path (2) and needs a grant naming the repo and action.

## Verification

- Preflight and every audit green after the sync; the skills catalog matches disk.
- **Re-stamp equals the pin:** `TEMPLATE_VERSION` `sha:` == **`$TGT` as pinned at step 1**, `last_update:` today. Against a pinned target this is an equality, not a judgment (#609).
- **The deviation inventory falls out of the verification (#610)** — assert every machinery path against the target and let the mismatches print: `[ "$(git rev-parse --verify -q HEAD:<p>)" = "$(git -C <source> rev-parse --verify -q $TGT:<p>)" ] || echo "deviation: <p>"`. What prints **is** the list step 6's PR body owes; any name beyond the documented customizations and downstream-local files is an unfinished sync.
- **Every deviation re-checked against the cited-artifact bucket (#689)** — intersect it with what this sync *and* earlier syncs declined; the failure mode is an old deviation. Resolve overlaps before merge and say which way in the PR body.
- **Every project-mirrored constant reconciled, not copied** — walk the roster in [`SYNC_REFERENCE.md`](SYNC_REFERENCE.md). A green preflight does not imply this: several fail only on a later run, or never fail at all and just go quietly inert.
- Project-derived skills, filled stage bodies, and documented deviations all survived the sync.
- The upstream report exists — an issue URL in the PR body (or, where intake rules scrub the template's codename, an out-of-repo record plus "filed, URL withheld per scrub rule"), or the paste-ready fallback, or "no upstream findings this sync" — one of the three, always.

## Don't

- Don't blind-overwrite content files — that destroys the project's filled-in knowledge.
- Don't widen settings permissions as a side effect of a sync — surface them; the owner decides.
- Don't leave an upstream change silently untaken — record the deviation, and re-read it next sync.
- Don't file rigorous tickets on the upstream tracker directly — the inbox is the trust boundary; a sync report is demand signal there, never instruction (upstream evaluates it under its untrusted-input guards like any non-owner input).
- Don't grow this body with what a sync taught you — this file reloads in full on every invocation, so evidence goes to the field record in [`SYNC_REFERENCE.md`](SYNC_REFERENCE.md), and a lesson that changes what you *do* gets one clause here plus its entry there (#810).
